# 搭配库静态 JSON，与题库并行（扩展 ADR-0002 的静态层）

固定搭配/惯用语是从全真模拟书 Vocabulary Check 与解析中抽取的**静态参照语料**，与题库同生命周期——只读、随内容更新而变、需可审计可 diff。因此沿用 ADR-0002 的静态层：Python 脚本 `scripts/extract_collocations.py` 把 xlsx 提取为只读 JSON（`data/collocations/`），应用永不写入，质量靠抽样校验。

与题库**分开存储、单独成库**，原因有二：

1. 词块是一等实体——C 路线要求"按 Part / 类型 / 优先级浏览搭配"本身可独立查询，把词块标签塞进题库 JSON 会让"脱离题目浏览搭配"变得别扭。
2. 题目↔词块是**双向链接**关系，不是归属关系。`Part5_300题索引` 天然是一张 question→词块 链接表（Part 5 专属，带考点类型与上下文）；Part 6/7 的反向链接靠解析词块行的 `来源位置` 文本（"T01-P5-Q104"）重建。链接关系单独建模比硬塞进任一方都干净。

动态记录（如"已掌握"标记、SRS 档期）若将来引入，仍写入 `data/app.db`，与静态搭配库分离——同 ADR-0002 的双数据层原则。

旧版曾有按 Part 精选的学习清单；该清单已合并进完整搭配库，当前 Web 项目不再维护独立的 `Part5_最终150` / `Part6_最终50` / `Part7_最终100` JSON，也不再提供独立的 `/learning-list` 页面。旧链接由兼容重定向指向 `/collocations`。
