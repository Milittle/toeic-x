# 单词本静态 JSON，与题库/搭配库并行（扩展 ADR-0002/0004）

单词是从《单词本》xlsx（NGSL 2809 + TSL 1250）提取的**静态参照语料**，与题库、搭配库同生命周期——只读、随内容更新而变、需可审计可 diff。因此沿用 ADR-0002/0004 的静态层：`scripts/extract_words.py` 把三份词表（重点1500 / TSL1250 / NGSL2809）提取为只读 `data/words/words.json`，每行标明所属词表，应用永不写入，质量靠抽样核对。

## 独立成库，而非并入 collocations.json

单词与搭配是两类一等实体、两套 schema、两个粒度：单词以「单词」为键（音标 / 释义 / 词频 / 推荐级别），搭配以「多词表达」为键（类型 / 本书频次 / 真题链接）。把当前 5559 行单词塞进以「表达」为键的搭配库会混淆两种粒度，正如 ADR-0004 当初拒绝把搭配并入题库。

单词 ↔ 搭配是**链接关系**，不是归属：单词行的「关联固定搭配」是文本标签，按表达文本去匹配 collocations.json，匹配上的在背单词页做成可点链接跳到 `/collocations/[id]`，匹配不上的当普通文字显示。真题可达性经搭配库中转，沿用搭配库已有的未见题样本保护（ADR-0004）；背单词页本身**不直接连任何题号**，单词的 Part5/6/7 次数是全书聚合计数（非题目定位），与搭配库公开显示 bookFreq 同口径，不构成泄露。

## 同一词属多份词表，故「词表 × 单词」为行、不去重

`refund` 同时在重点1500 与 TSL1250 两份词表里、数据一致。词库以「词表 × 单词」为行存（每行带 `list` 字段），同一单词在不同词表里各占一行；背单词页按词表分 Tab 浏览。这是「记单词 = 背某份词表」心智的直接映射，也避免去重后丢失"某词属于哪几份词表"的信息。

## 不引入数据库表

背单词页是纯浏览参考：无自我测试、无掌握状态、无 SRS 排期，没有任何需要持久化的用户状态，因此不进 `data/app.db`。xlsx 里那个空的「掌握状态」列当前不用。将来若要做主动回忆 / 单词级排期，再按 ADR-0002 的双数据层把单词级动态状态写入 app.db，与静态词库分离——同题库 / 搭配库的双层原则。
